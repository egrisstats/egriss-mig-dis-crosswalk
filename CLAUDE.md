# Notes for editing this repo

- Plain HTML, CSS and JavaScript. No framework, no build. Test by opening the pages in a browser.
- `crosswalk.js` holds everything for the crosswalk: `PARAS` (quoted paragraphs with highlighted parts), `R` (refugee routes: category, type of stay, resident group, case, example, rule, reference, likelihood), `NEST` (refugee cases), `FLOWA` and `FLOWB` (IDP graphs with their cases), and the drawing code.
- `story.js` is the walk-through: one step per screen with snap scrolling, a caption above the graph, and the graph built from HTML cards with the routes drawn between them after layout. It reads the data in `crosswalk.js` (`CATS`, `LINKS`, `MID`, `MIDLAB`, `CELLS`, `NEST`, `GFULL`, `FLOWA`, `FLOWB`); the hidden crosswalk markup in `story.html` is there so `crosswalk.js` can run. Steps live in the `STEPS` array: each can set `build` (columns shown: L, M, R, sq, links), `hide` (node ids), `focus` (`col:L|M|R`, `node:<id>`, `gate`, `frame`), `exp` (expected-route case) and `cases`. The step before it sets `ugmap`: the graph columns hide and a map of Uganda (`uganda-map.js`, Natural Earth 1:50m projected to SVG paths) shows 2025 arrivals, returns and the people already in the country, with a key saying which route each group takes. The last step sets `uga`: it draws the Uganda example from the `UGA` constant, with line thickness scaled to people (UNHCR end-2025 figures, births estimated from the under-5 count, UN DESA 2024 migrant stock).
- Case types: E expected, 1 never moved, 2 not yet or not visible, 3 migrant for a different reason, 4 counted differently, 5 misalignment.
- Writing conventions: never use en dashes; call IRRS, IRIS and IROSS "recommendations", never "standards"; examples use "a woman", "a man", "a child", not personal names.
